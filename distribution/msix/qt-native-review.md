# Original Qt native collector integration

The command-line native collector now always verifies all five current Qt modules against their fixed original Qt 6.11.2 Windows archives. Each shipped native path is selected from the original binary SPDX inventory and must have exactly one original module owner. The actual plugin-to-`bin` and preserved QML layouts are checked without leaf-name or hash-only adoption. Unshipped tools and foreign files do not acquire Qt provenance.

Current SDK binary/source metadata must match the fixed original metadata hashes, and those exact metadata bytes and current shipped native bytes must also match regular members of the original archives. The existing production CMake/LibArchive checks preserve archive/tool hashes, stable files, Windows path aliases and extraction bounds. All ten original metadata files are retained once under `build-evidence/native-source/qt/sbom`; the workflow adds only those `.json`/`.spdx` metadata paths. No runtime binaries are uploaded or changed.

Five new production regression cases pass, including real archive comparison, changed current metadata/archive/runtime, incomplete/duplicate module sets, aliased/traversing original paths, ambiguous ownership, non-adoption of unshipped files and exclusive metadata retention. The production collector was also run locally against all five actual original SDK archives and the actual stage inventory from run 34697625639: all 53 shipped Qt native files match. This is macOS archive comparison, not a new Windows consumer or installed result.

The complete preferred-source comparisons and notice proofs are separately retained. The collector still reports `sourceLicenseClosure: false` while the remaining source/publication and Microsoft runtime checks are integrated. In particular, the older D3D compiler in Qt's cache is not asserted to own the different current staged D3D compiler; the current Windows SDK redistributable candidate still requires independent native origin observation.
