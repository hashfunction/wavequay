# WaveWeft Windows packages and corresponding source

The Windows workflow preserves the existing staged consumer qualification, then
compares complete current native provenance, preferred source and original
notices. It builds two fixed MSIX identities from the same current stage:

| Mode | Name | Publisher | Application ID |
| --- | --- | --- | --- |
| `qualification` (default) | `Trieflow.WaveQuay.Qualification` | `CN=WaveQuay-CI-Qualification` | `WaveQuay` |
| `store` | `1659hashfunction.WaveQuay` | `CN=B6A2631A-FD32-45CC-AE12-82466975F528` | `WaveQuay` |

Both use WaveWeft 1.0.1.0, `bin/WaveWeft.exe`, x64 and Windows Desktop/full trust.
The assigned Store family is `1659hashfunction.WaveQuay_r3hxytd7jt6c4` and publisher
display is `hashfunction`. Product branding does not change compatibility data
namespaces or the existing package identity. Arbitrary identities are refused.

Each installation refuses existing same-name registrations and package data. A
nonexportable, temporary certificate signs a copy of the unsigned MSIX. Normal
package activation supplies the real package process and Windows broker
environment. The observer retains the exact package/PID/process lifetime and
runs the real import, Reverse, project save/reopen, recipe save/apply and two WAV
exports. The unchanged independent file oracle checks the actual SQLite project,
complete reversed six-second stereo PCM and recipe metadata after normal close.
It then removes only the exact owned fixture and profile snapshot. Package data
cleanup is delegated to the exact package uninstall and independently checked.
Temporary trust, personal certificate/key and signing files must also be gone.

The final exporter independently requires the same repository, source commit,
run and attempt across original native, package and installed receipts. It
regenerates the payload, manifest, artwork and source notices from current
inputs, checks both unsigned containers and their original SDK records, and
replays the original GUI/screenshots, complete input/readback sequence and file
oracle metadata. The original JSON snapshots have exact retained byte hashes;
the exporter does not claim to reparse media or projects already removed by the
owned cleanup. A staged workflow cannot substitute for either installed result.

Every package includes 532 unchanged original application/component notices,
five separately scoped original Microsoft terms/distributable lists,
`SOURCE-INFO.json` and `SOURCE-README.txt`. The source comparison joins the actual
consumed native files to their original archives, preferred source or exact
Microsoft installation origins. It compares all 40 published preferred-source
archives, original notices and original Qt SPDX/member proofs. Original archive
collection URLs remain historical evidence; the exact delivery mapping uses the
public WaveWeft source release. Current application source and both pinned
submodule trees must independently match complete anonymous public GitHub
commit/tree responses. No token or private source endpoint is used.

Only after all gates pass does the workflow upload exactly:

- `WaveWeft_1.0.1.0_x64.msix`, untouched and unsigned;
- `store-export.json`, the final source/run/package/evidence receipt.

Metadata, original UI trees/screenshots and bounded owned diagnostics are a
separate artifact on failure. No signed package, private key, certificate, raw
fixture WAV/project or user profile is included. Store submission/certification
and hardware recording/playback qualification remain separate. The source
comparison documents actual component origins and retained license terms; it
is not a blanket legal opinion or an application-wide Microsoft license.

An explicit `capture_accessibility_graph=true` dispatch is always a rejected
diagnostic observation. It retains bounded new provenance errors and the same
owned staged observer, with no installed lifecycle or Store export. Normal runs
retain immediate provenance failure and all original acceptance/cleanup checks.

The actual complete Windows source/origin and installed export results remain
pending at this source handoff. Local fixture results are not native acceptance.
